Toolbox 插件化工具箱

基于 .NET 10 / C# 14 / WPF 的插件化工具箱：每个插件跑在独立的可回收 AssemblyLoadContext 里，卸载后强制 GC 验证真回收；无边框自定义标题栏、启动画面、 Ctrl+K 命令面板、深/浅主题（深色内测）与全套动效。

版本 1.0.0-beta 构建 0 警告 0 错误 宿主 80 项断言全绿 卸载 1 轮 GC 即回收 自包含 · 免装 .NET
下载安装包（51 MB） 便携版 zip（71 MB）

核心功能

一个能跑、能验证、能卸载的插件化骨架 —— 不是演示，是完整产品。

ALC

真·插件隔离与卸载

收集式 AssemblyLoadContext + AssemblyDependencyResolver；卸载走「摘视图 → Shutdown → 释放容器 → Unload → 强制 GC」协议，回收结果写进日志与结果历史。

＋

添加工具 / 插件市场

左栏一键安装 zip / dll / 文件夹并立即加载；插件市场（内测·敬请期待）浏览本地 market/ 目录，空市场自动播种，支持从文件安装。

⌘K

Ctrl+K 命令面板

搜插件、打开/卸载/重载、运行工具、切主题、跳设置与关于；↑↓ 选择、Enter 执行、Esc 关闭。

UI

无边框 + 全套动效

WindowChrome 自绘标题栏（拖拽/双击最大化/右上三键）、启动画面、工具栏折叠动画、列表强调条、日志逐行淡入——且绝不给插件视图挂动画。

◑

调色板整体换肤（DynamicResource），暗色对比度专门调过；主题、字号缩放、关窗行为、开机自启全部持久化。

快速开始

方式一：安装（推荐）

  • 运行 Toolbox-Setup-1.0.0-beta.exe（简体中文向导，按用户安装、无需管理员）
  • 安装完从开始菜单或桌面快捷方式启动；卸载入口在 Windows「应用和功能」里
  • 自包含发布：目标机器不需要装 .NET

方式二：便携版

  • 解压 Toolbox-win-x64.zip 到任意目录，双击 Toolbox.App.exe
  • 插件放 plugins/、配置在 appsettings.json、日志在 logs/
  • 仓库根目录的「Toolbox 启动 / Toolbox 安装包」快捷方式直达这两个产物
开发者：克隆仓库后跑 pwsh ./scripts/verify.ps1 一键「构建 → stage 插件 → 80 项宿主断言」； GUI 验证依次是 ui-smoke.ps1（20 项）与 ui-redesign-smoke.ps1（82 项）。

使用教程

从打开第一个插件到管理整个工具箱，五步上手。

一、打开与操作插件

单击 = 直接打开

左侧列表里单击任意插件：未加载会自动加载，并把它的界面标签页切到前台；列表顶部的过滤框可按名称/Id 实时筛选。

右键 = 单插件菜单

打开 / 卸载（会验证 ALC 真回收）/ 重载（换一个新 ALC）/ 删除插件（带确认，连文件一起从磁盘移除）。

看结果

右侧「结果历史」保留每次加载、卸载、运行、导出的记录：可单条复制、复制全部、导出 txt、一键清空。

二、键盘与命令面板

快捷键 / 入口作用
Ctrl + K呼出命令面板：搜插件、执行动作、运行工具、切主题、打开设置/关于/市场
↑ ↓ / Enter / Esc面板内选择 / 执行 / 关闭
左栏「日志」中间区域在「插件界面 ⇄ 实时日志」之间切换（只改可见性，不影响卸载）
左栏顶部折叠键工具栏在「图标+文字 ⇄ 纯图标」之间折叠（带宽度动画）
标题栏 ─ □ ✕最小化 / 最大化 / 关闭（关闭默认进托盘，托盘右键可真正退出）

三、安装新插件的三种姿势

左栏「添加工具」

选插件包（.zip / .dll）或文件夹 → 复制进 plugins/ → 立即加载。单个 .dll 会自动落成同名子目录，重启后照样能被扫描到。

插件市场（内测 · 敬请期待）

浏览本地 market/ 目录（与已安装目录分离，不会被自动加载），一键安装即加载；也支持「从文件安装」。空市场会自动播种一个可安装的示例包。

直接放文件

把目录或 zip 丢进 plugins/，然后在 设置 → 目录 → 「重新扫描插件目录」。

四、外观与启动（设置 → 分类在左、内容在右）

外观

浅色 / 深色一键切换（深色带「内测」标签）；字号缩放 100% / 125% / 150%，主窗口同步放大，超出屏幕正文区自动出滚动条。

启动与托盘

「关窗最小化到托盘」可关（关掉后点关闭=直接退出）；「开机自启」写 HKCU Run（仅当前用户、免管理员）。

目录

插件/影子/数据/日志四个路径一览；重新扫描、重新加载、一键打开对应文件夹。

插件宿主 / 覆盖 / 配置文件

共享程序集、卸载验证参数、插件配置覆盖（plugin.json < appsettings.json）与配置文件位置，全部只读展示。

五、主题与细节

  • 深色（内测）：设置→外观或 Ctrl+K「切换主题」；暗色对比度、菜单、悬停层都单独调过，选择记忆在 %LOCALAPPDATA%\Toolbox\theme.txt。
  • 左上角图标：头像位就是软件图标（悬停放大、选中出现光环）。
  • 启动参数：--theme dark / --theme light 临时覆盖主题（不写回偏好）。

教程：写一个插件（3 步）

契约层零依赖；宿主提供 Toolbox.Contracts.dll，插件绝不复制它。

建工程

dotnet new classlib -n Acme.Toolbox.MyPlugin -o plugins/Acme.Toolbox.MyPlugin

csproj：开启动态加载 + 引用契约（不复制）

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <EnableDynamicLoading>true</EnableDynamicLoading>
  </PropertyGroup>
  <ItemGroup>
    <!-- 关键：契约由宿主提供，绝不复制进插件目录 -->
    <ProjectReference Include="..\..\src\Toolbox.Contracts\Toolbox.Contracts.csproj"
                      Private="false" ExcludeAssets="runtime" />
  </ItemGroup>
</Project>

写插件入口（可选再实现带界面的工具）

using Toolbox.Contracts;

[ToolboxPlugin("acme.myplugin", DisplayName = "我的插件", Version = "1.0.0")]
public sealed class MyPlugin : IToolboxPlugin
{
    public ValueTask InitializeAsync(IPluginContext context, CancellationToken ct = default)
    {
        context.Logger.LogInformation($"初始化完成，数据目录 {context.DataDirectory}");
        return ValueTask.CompletedTask;
    }

    public ValueTask ShutdownAsync(CancellationToken ct = default)
        => ValueTask.CompletedTask;  // 卸载纪律：清干净自己的引用
}

发布与安装

  • 目录插件：把构建输出整个放进 plugins/<名字>/；
  • zip 插件：内容打包为 plugins/<名字>-<版本>.zip（多于一个 dll 时必须带 plugin.json 指定 entryAssembly）；
  • 装完在 设置→目录「重新扫描」，或直接用左栏「添加工具」一步到位。
三条红线（否则卸载回收必失败）：① 视图类不要派生 WPF 类型、不要用 BAML/XAML； ② 不要把插件类型/实例塞进宿主 DI、静态字段或默认 ALC 的缓存； ③ 不要给插件视图挂动画/Effect —— 动画计时器会把插件对象钉死。详见 docs/DESIGN.md。

已知边界 / FAQ

  • 插件是完全信任代码：ALC 不是安全沙箱，权限隔离需要另起进程。
  • 卸载是协作式弱保证：附加调试器/诊断工具或残留引用时可能回收失败，日志会明确报「未被回收」。
  • 同一个插件 Id 的目录形态与 zip 形态不要同时放进 plugins/（会被当成热替换）。
  • 深色主题是内测：宿主全面换肤，但插件自带界面仍为浅色（宿主不越权改插件的配色）。
  • 宿主不能裁剪/NativeAOT/单文件发布（会破坏反射发现与动态加载）。
  • UI 自动化客户端持有插件元素会钉住 ALC —— 测试脚本在卸载前会主动释放引用并触发 GC。
